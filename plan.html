🍻 Khởi Nghiệp

Game mô phỏng kinh doanh 3D — bắt đầu với quán nhậu, mở rộng sang quán cafe và quán nước. Kế hoạch phát triển chia thành 10 giai đoạn, từ dựng khung đến phát hành.

Engine

Unity + URP

Ngôn ngữ

C#

Giao diện

UI Toolkit (UXML + USS)

Nền tảng

Mobile landscape → PC

Input

Input System (touch + chuột)

Dữ liệu

Offline-first, sẵn sàng server

Kiến trúc

Feature-based + asmdef

Đồ họa

Khối primitive → model sau

Đa ngôn ngữ

Localization từ ngày đầu (vi + en)

Dựng khung dự án & cấu hình nền tảng

Móng nhà — làm đúng một lần, đỡ cực về sau
Nền tảng
Mục tiêu: Có cấu trúc thư mục sạch, chuẩn, dễ bảo trì; project cấu hình sẵn cho mobile landscape.

Cấu trúc thư mục (feature-based)

Assets/
  _Project/                      ← đồ của mình, tách khỏi asset bên thứ 3
    Scripts/
      Core/
        SceneFlow/               ← SceneLoader, SceneNames
        Bootstrap/               ← khởi động game
      Features/
        Splash/
        MainMenu/
        BarGame/                 ← quán nhậu (làm sau)
      Data/                      ← IDataStore, LocalDataStore
      Shared/                    ← helper, extension dùng chung
    UI/
      Splash/                    ← Splash.uxml + Splash.uss
      MainMenu/                  ← MainMenu.uxml + MainMenu.uss
      Shared/                    ← theme chung (biến màu, font)
    Scenes/
      Splash.unity
      MainMenu.unity
      BarGame.unity
    Settings/                    ← config (ScriptableObject sau này)

Công việc

  • Tạo cây thư mục _Project/ như trên.
  • Cấu hình Player Settings: khóa màn hình Landscape Left + Right, tắt Portrait.
  • Đặt Company Name / Product Name = "Khởi Nghiệp".
  • Thiết lập Assembly Definitions (asmdef) cho từng module: Core, Features.Splash, Features.MainMenu, Data... ép ranh giới phụ thuộc rõ ràng.
  • Quy ước namespace: KhoiNghiep.Core, KhoiNghiep.Features.MainMenu...
  • Xác nhận URP Mobile_Renderer được dùng mặc định cho build mobile.
✅ Hoàn thành khi: Project mở không lỗi compile, thư mục gọn gàng, bật Play ở Editor chạy bình thường, orientation khóa ngang.

Splash Screen & luồng chuyển màn

Màn hình đầu tiên người chơi thấy
Nền tảng
Mục tiêu: Hiện logo game vài giây rồi tự chuyển sang Main Menu, qua một hệ thống chuyển scene tập trung.

Công việc

  • Viết SceneLoader (Core/SceneFlow): một nơi duy nhất lo việc chuyển scene — giống router bên web.
  • Tạo SceneNames: hằng số tên scene, tránh gõ chuỗi tay dễ sai.
  • Thiết kế Splash bằng UI Toolkit: Splash.uxml (bố cục) + Splash.uss (style), hiện logo + tên game.
  • Script SplashController: chờ 2–3 giây (hoặc chờ load xong) → gọi SceneLoader sang MainMenu.
  • Phân biệt rõ với Unity splash (logo "Made with Unity") — cái đó của engine, cái này là của game.
✅ Hoàn thành khi: Bật Play từ scene Splash → thấy logo → tự nhảy sang Main Menu.

Main Menu & chọn loại quán

Trang chủ — nơi chọn trò chơi
Nền tảng
Mục tiêu: Trang chủ hiển thị tên game + 3 nút chọn quán. Bấm "Quán Nhậu" vào màn chơi; 2 loại còn lại tạm khóa.

Công việc

  • MainMenu.uxml + MainMenu.uss: tiêu đề "Khởi Nghiệp" + 3 nút: Quán Nhậu (mở), Quán Cafe (khóa 🔒), Quán Nước (khóa 🔒).
  • MainMenuController: xử lý sự kiện click nút, gọi SceneLoader sang BarGame.
  • Thiết kế để dễ thêm loại quán mới sau này (danh sách quán dạng dữ liệu, không hardcode).
  • Thêm nút Thoát (PC), nút Cài đặt (placeholder) và nút đổi ngôn ngữ (vi/en).

Responsive, Safe Area & Input (gộp chung)

  • UI Toolkit dùng đơn vị % và flexbox (giống web) để co giãn tự động trên mọi tỉ lệ màn hình.
  • Xử lý Safe Area: chừa viền tai thỏ, góc bo trên điện thoại.
  • Tạo theme USS dùng chung (Shared): biến màu, font, khoảng cách — đổi một chỗ, cả game đổi theo.
  • Thiết lập Input System: gộp touch + mouse thành "pointer" chung, viết một lần chạy cả hai.
  • Test nhanh ở nhiều tỉ lệ trong Game View (16:9, 19.5:9, 4:3 iPad).
✅ Hoàn thành khi: Splash → Menu → bấm Quán Nhậu → sang scene BarGame (tạm trống); 2 nút kia khóa; UI hiển thị đúng ở nhiều tỉ lệ; chạm và click đều chạy.

Hệ thống đa ngôn ngữ (Localization)

Làm sớm để mọi text sau này đều đi qua hệ thống này
Nền tảng
Mục tiêu: Dựng hệ thống dịch đa ngôn ngữ bằng Unity Localization. Từ đây, MỌI chuỗi hiển thị cho người chơi đều lấy từ String Table — không hardcode chữ trong code hay UXML.

Cách hoạt động

String Table (key → giá trị theo từng ngôn ngữ)
  menu_title   | vi: "Khởi Nghiệp"     | en: "Startup"
  btn_start    | vi: "Bắt đầu"          | en: "Start"
  hud_money    | vi: "Tiền: {0}"        | en: "Money: {0}"   ← Smart String
        │
   LocalizedString  ← UI/code tham chiếu bằng KEY, tự đổi khi đổi ngôn ngữ

Công việc

  • Cài package com.unity.localization.
  • Tạo Locales: Tiếng Việt (vi) mặc định + English (en).
  • Tạo String Tables theo nhóm key: common_, splash_, menu_, bargame_, hud_, shop_.
  • Chuyển hết text của Splash + Main Menu (đã làm) sang dùng LocalizedString theo key.
  • Dùng Smart String cho chuỗi có biến (tiền, số lượng, số nhiều) — không nối chuỗi thủ công.
  • Nút đổi ngôn ngữ đổi locale lúc đang chạy, UI tự cập nhật (không cần khởi động lại).
  • Chọn font bao phủ ký tự của các ngôn ngữ hỗ trợ.
  • Cấu trúc để thêm ngôn ngữ mới = thêm một cột, không sửa code.
✅ Hoàn thành khi: Bấm nút đổi ngôn ngữ ở Menu → toàn bộ chữ đổi vi ↔ en ngay lập tức. Không còn chuỗi hardcode nào trong Splash/Menu.

Màn chơi quán nhậu — bối cảnh & camera

Dựng sân khấu cho gameplay
Gameplay
Mục tiêu: Scene BarGame có sàn nhà, vài cái bàn, camera góc tycoon, ánh sáng — tất cả bằng khối primitive.

Công việc

  • Dựng sàn nhà + tường đơn giản (khối hộp).
  • Đặt 3–4 cái bàn: mỗi bàn = mặt bàn + 4 chân + chỗ ngồi (prefab Table).
  • Camera góc nhìn chéo từ trên xuống (tycoon), cố định hoặc kéo nhẹ.
  • Ánh sáng cơ bản (Directional Light) hợp URP mobile.
  • Prefab hóa bàn để dễ nhân bản và sau này thay bằng model đẹp.
✅ Hoàn thành khi: Vào BarGame thấy một không gian quán 3D với bàn ghế, camera nhìn bao quát.

Khách hàng — vòng đời & di chuyển

Trái tim của game mô phỏng
Gameplay
Mục tiêu: Khách tự xuất hiện ở cửa, tìm bàn trống, đi tới ngồi, chờ được phục vụ, rồi rời đi.

Máy trạng thái khách (state machine)

Vào cửa → Tìm bàn trống → Đi tới bàn → Ngồi/Gọi món
   → Chờ phục vụ → Ăn/uống → Trả tiền → Rời đi

Công việc

  • CustomerSpawner: sinh khách theo thời gian (capsule + cầu làm đầu).
  • Customer state machine: quản lý từng trạng thái ở trên.
  • Di chuyển khách tới bàn (NavMesh hoặc di chuyển đơn giản theo điểm).
  • Table: biết trống/đang có khách; khách không giành cùng một bàn.
  • Nếu hết bàn → khách chờ hoặc bỏ đi (ảnh hưởng điểm sau này).
✅ Hoàn thành khi: Bật Play thấy khách tự vào, tự ngồi vào bàn trống, chờ một lúc rồi rời đi.
7

Gọi món, phục vụ & kiếm tiền

Vòng lặp cốt lõi: phục vụ → nhận tiền
Gameplay
Mục tiêu: Khách gọi món, hiện yêu cầu trên đầu; người chơi click để phục vụ; phục vụ xong khách trả tiền.

Công việc

  • OrderSystem: khách gọi 1 món (bia, mồi nhậu...), hiện icon "!" / bong bóng trên đầu.
  • Click chuột / chạm vào khách để phục vụ (dùng pointer chung từ Giai đoạn 4).
  • Phục vụ xong → khách ăn/uống trong vài giây → trả tiền.
  • EconomyManager: cộng tiền, theo dõi tổng doanh thu.
  • Khách chờ quá lâu → mất kiên nhẫn → bỏ đi, không trả tiền (tạo áp lực gameplay).
  • 🌐 Tên món và mọi text hiển thị dùng key localization (bargame_), không hardcode.
✅ Hoàn thành khi: Vòng lặp hoàn chỉnh: khách vào → gọi món → click phục vụ → nhận tiền → tiền tăng trên UI.

HUD trong game, tiền & lưu dữ liệu offline

Hiển thị thông tin & giữ tiến trình
Gameplay
Mục tiêu: HUD hiển thị tiền, số khách, thời gian; dữ liệu game lưu được trên máy và nạp lại khi mở lại.

Lớp dữ liệu (sẵn sàng cho server)

IDataStore            ← hợp đồng lưu/đọc dữ liệu
   ├── LocalDataStore    ← bây giờ: lưu file JSON trên máy
   └── ServerDataStore   ← sau này: gọi API server (chưa làm)

Công việc

  • HUD (UI Toolkit): hiển thị tiền, số khách đã phục vụ, nút Pause.
  • Menu Pause: Tiếp tục / Về trang chủ.
  • IDataStore + LocalDataStore: lưu tiền và tiến trình ra JSON trên máy.
  • Gameplay chỉ nói chuyện với IDataStore — sau đổi sang server chỉ thay phần ruột.
  • Tự lưu khi thoát, tự nạp khi vào lại.
  • 🌐 Mọi nhãn HUD và menu Pause dùng key localization (hud_, common_) + Smart String cho số tiền.
  • Lưu luôn ngôn ngữ đã chọn vào dữ liệu để lần sau mở lại giữ nguyên.
✅ Hoàn thành khi: Chơi, kiếm tiền, thoát ra, mở lại → tiền, tiến trình và ngôn ngữ vẫn còn.

Chiều sâu: nâng cấp, nhân viên, nguyên liệu

Biến prototype thành game thực thụ
Gameplay
Mục tiêu: Thêm hệ thống phát triển để người chơi có mục tiêu dài hạn và lý do chơi tiếp.

Công việc (chọn làm dần)

  • Nâng cấp quán: mua thêm bàn, mở rộng không gian.
  • Thuê nhân viên: bồi bàn tự phục vụ, đầu bếp làm món nhanh hơn.
  • Nguyên liệu / menu: mua nguyên liệu, thêm nhiều món với giá khác nhau.
  • Tiến trình theo cấp: mở khóa Quán Cafe / Quán Nước khi đạt mốc tiền.
  • Cân bằng kinh tế (giá món, lương nhân viên, tốc độ khách) — để trong ScriptableObject để chỉnh không cần sửa code.
  • 🌐 Tên nâng cấp, nhân viên, nguyên liệu dùng key localization (shop_), không hardcode.
✅ Hoàn thành khi: Người chơi có thể tái đầu tư tiền để quán lớn dần, mở khóa loại quán mới.

Đồ họa, âm thanh, build & phát hành

Hoàn thiện & đưa lên điện thoại
Hoàn thiện
Mục tiêu: Thay khối hộp bằng model đẹp, thêm âm thanh, tối ưu hiệu năng, build ra Android để chơi thật.

Công việc

  • Thay model: tải model miễn phí (Kenney.nl, Asset Store, Poly Pizza) hoặc tự làm bằng Blender — thay vào chỗ khối hộp, không phải sửa code logic.
  • Âm thanh: nhạc nền, tiếng click, tiếng khách, tiếng nhận tiền.
  • Hiệu ứng: animation khách, particle khi nhận tiền.
  • Tối ưu mobile: kiểm tra FPS, giảm draw call, nén texture.
  • Build Android (.apk): test cảm giác chạm, hiệu năng trên máy thật.
  • 🌐 Rà soát localization: kiểm tra không còn chuỗi hardcode, font hiển thị đủ ký tự mọi ngôn ngữ, bố cục không vỡ khi chữ dài hơn (en thường dài hơn vi). Cân nhắc thêm ngôn ngữ mới.
  • (Tùy chọn) Thêm server: viết ServerDataStore + backend cho đăng nhập, lưu cloud, xếp hạng.
✅ Hoàn thành khi: Có file .apk cài được lên điện thoại, chơi mượt, nhìn chỉn chu hơn bản prototype, đổi ngôn ngữ chạy đúng không vỡ layout.
